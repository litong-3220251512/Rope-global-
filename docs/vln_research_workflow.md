# VLN 科研工作流与 agent 职责

制定日期：2026-10-18。适用于后续 VLN 研究；通用证据规则也适用于当前 RoPE / CLEVR 工作。本文是项目操作规范，不是经过实验验证的科研效率结论。依据与取舍见 [调研来源](research_workflow_sources.md)，权限以 [AGENTS.md](../AGENTS.md) 为准。

## 1. 科研状态与进入条件

| 阶段 | 必须形成的可审查产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 界定任务 | 问题、数据集/split、观测与动作、预算、可用本地资产、未知项 | 比较对象和可用信息可明确描述 |
| 文献核验 | 论文证据表、近邻方法及反对证据、候选基线的条件对照 | 关键断言能定位到原文；未知项显式列出 |
| 机制定义 | 基线与改动的数学说明、模块位置、手算例子、证伪预测 | 定义完整，不变量与边界检查成立 |
| 实验设计 | 预先登记主比较、指标、seeds、预算、消融、checkpoint 规则 | 比较公平，评估固定；数据/权重由用户提供 |
| 最小实现 | 独立分支、官方库选型、必要回归证据、真实 PR | 数学规格与实现一致；未覆盖项明确 |
| 实验交接 | 精确命令、环境、输入输出、预计资源及异常退出行为 | 用户明确授权相应冒烟或正式运行 |
| 结果审计 | 原始结果清单、逐 episode 复算、全部 seeds、失败记录 | 数据来源和计算过程可追溯，不完整处已标注 |
| 质疑与写作 | 替代解释检查、断言—证据映射、限制、下一步 | 表述强度不超过证据；没有隐藏失败或测试集调参 |

这不是要求每轮聊天重复八步。只执行当前请求需要的阶段；已有合格记录可直接引用。文献可继续检索，实验启动必须等待用户明确指令。运行后不自动轮询日志、GPU 或进程。

## 2. Agent 分工与权限

以下是职责设计，不代表已启动六个后台代理。单个代理可以分阶段履行这些职责，但不得把自查称作独立评审。

| 角色 | 输入与输出 | 可修改内容 | 不得自行决定 |
| --- | --- | --- | --- |
| 研究协调者 | 用户目标 → 范围、当前阶段、缺口和交接 | 计划、状态、决策记录 | 更换研究主线、追加训练预算 |
| 文献核验者 | 明确问题 → 原文位置、条件、支持/反对证据 | 文献与证据记录 | 仅凭摘要下定论、宣称最新 SOTA |
| 机制设计者 | 证据中的失败模式 → 数学定义、最小改动、反例与消融 | 方法说明、实验草案 | 把假设提升为结论、跳过推导实现 |
| 实现者 | 已定义的方法与接口 → 最小 patch、测试、PR | 授权范围内的源代码和配置 | 改评估标准、下载资产、启动实验 |
| 结果审计者 | 用户提供的原始输出 → 独立复算和有限结论 | 派生分析产物；原始数据只读 | 补造缺失运行、剔除失败以美化结果 |
| 质疑审查者 | 完整方法与证据 → 混杂、泄漏、反例和过强断言清单 | 审查记录 | 改结果、投票决定科学真伪 |

任务交接写清输入位置、输出位置、允许改动、禁止动作及完成标准。并行任务必须相互独立；实现不能在数学定义仍变化时与方法设计同时修改同一模块。

评估器、split、原始输出属于固定面；方法模块属于本轮约定的可编辑面；失败记录和结论更正追加保存。若发现评估器错误，独立修复并重评所有受影响结果，不能把新旧协议结果混在同一比较中。

## 3. Skill 路由

| 当前工作 | 可用时优先考虑 | 使用方式 |
| --- | --- | --- |
| 单篇论文核读 | `paper-reading-card` | 结构化记录问题、方法、结果、局限；回到原文核对 |
| 方法与实验设计 | 与实际投稿 venue 匹配的 experiments / related-work skill | 只加载对应任务所需材料，避免同时叠加多个 venue 流程 |
| 科研权限与状态设计 | `harness-engineering` | 固定评估面、记录失败、分离生成与审查 |
| 工程诊断/实现 | `diagnose` 或 `superpowers:systematic-debugging`；必要的测试与代码审查 skill | 按已确认根因修改；测试实现，不宣称验证科研效果 |
| 论文写作 | `academic-writing` 或 `embodied-ai-paper-writer` | 从核实的证据写作；不得为故事完整补造结果 |

外部仓库中的 `scientific-critical-thinking`、`ml-paper-writing`、`results-analysis` 等是本次调研参考，不默认宣称已经安装。未来采用时先检查本机是否可用、版本、许可证与权限冲突；用户未要求安装时，不运行整套安装器。

不按 stars 自动选工具，不把所有 skills 放进常驻上下文。核心规则保留在 `AGENTS.md`，细节按需读取。外部 skill 要求下载、自动训练、自动监控、调用付费服务或发布内容时，以用户授权和仓库边界为准。

## 4. 证据记录模板

对会影响选题、实现或论文结论的断言建立以下记录；普通背景说明不必逐句复制模板。

```text
断言编号 / 原句：
类型：论文报告 / 本地观测 / 数学推导 / 待验证假设
来源：论文稳定链接或真实结果文件
定位：版本、章节、公式、表/图、行/列；本地结果的运行/episode 范围
实验条件：数据集、split、观测/动作、预训练与额外数据、预算
已核实内容：
相反证据 / 替代解释：
允许的表述：
证据不支持的更强表述：
未知项及解决它需要的证据：
核查日期 / 更正历史：
```

“论文报告有效”不能写成“我们验证有效”。“尚未找到相关工作”不能写成“首次提出”。数学推导只在列出的假设下成立；推导不能代替统计证据。新方法预期收益标为预测，不给出没有依据的百分点。

## 5. 方法提案模板

```text
问题与范围：具体什么输入/轨迹/现象失败；证据在哪里
基线：论文、版本、官方实现、任务与观测假设
近邻方法：哪里相同、哪里不同；尚未核实的相关工作
改动类型：loss / reward / architecture（至少一个）
原定义 → 新定义：完整公式、输入输出形状、符号与坐标系
改动位置：实际文件/类/函数；未检查代码时标“待定位”
监督/信号：来源、训练与推理可用性、是否涉及特权信息
优化细节：梯度、归一化、权重、退化回基线的设置
资源变化：参数、FLOPs/延迟/显存、数据、额外训练
数学检查：不变量、边界、手算例子、失败反例
机制预测：什么可观测结果应出现，为什么
证伪结果：什么结果会使机制解释不成立或需削弱
消融：单独模块、容量/计算匹配控制、适用时的去除/干预实验
超参数依据：原论文 / 推导 / 预先声明的验证搜索
当前状态：仅提案 / 可实现 / 等待资产 / 等待用户启动 / 已有证据
```

数学说明须足以让另一位实现者无需猜测主要机制。损失项只写名字、奖励只写“更合理”、架构只画空框，均视为定义未完成。

提案至少满足以下对应要求：

- **损失**：把新增项展开为具体变量运算，说明标签从何而来、缺失标签如何处理以及哪些参数更新。仅写 `L = L_base + α L_new` 不合格。
- **奖励**：明确每一步与终止奖励，区分训练 oracle 与推理输入；列出绕圈、过早停止、仅优化进度代理等可能的投机路径。不能未经推导宣称 reward shaping 保持最优策略。
- **架构**：标出新增/替换算子与信息路径、序列/空间索引和 mask；说明分辨率、坐标原点、变长轨迹及空候选动作的行为。空间位置编码不得偷用未来轨迹或目标真值。

一个“可定位的架构修改”实例是 DUET §3.2 Eq. (3)–(4) 的图距离 attention bias，Table 2 对该项做了消融；这里只用它示范描述颗粒度，不提出把它当成本项目新贡献。[论文](https://arxiv.org/pdf/2202.11742)

## 6. VLN 比较前的协议清单

为每个候选基线填同一份表；缺失项写“未知”。

| 项目 | 需要明确的内容 |
| --- | --- |
| 任务 | 数据集/版本/split、图导航或连续环境、指令类型与语言 |
| 输入 | 单目/双目/全景、RGB/深度、位姿、地图、历史、目标线索、FOV |
| 动作 | 离散候选点或低层控制、步长/转角、碰撞/滑动设置、STOP 和最大步数 |
| 训练 | 用户提供的权重/预训练/额外数据、冻结层、优化器、seed 与更新预算 |
| 可用信息 | 每项信息在训练/验证/推理时的来源，是否用到 oracle |
| 评估 | 官方评估器及版本、距离/成功定义、主要和次要指标、checkpoint 选择 |
| 公平性 | 容量、计算、训练/搜索预算、传感器、episode 与非改动因素 |
| 统计 | 独立单位、配对方式、场景/指令依赖、seeds、区间方法及其假设 |

官方成功阈值是 benchmark 定义的一部分，不能为了改善结果改动。策略里新增的经验阈值则属于待审查的方法选择，不能冒充统一规律。没有文献或定义支持时，不虚构通用的成功半径、步数或最低提升百分点。

不能默认一种传感器配置下的领先方法适合另一种配置。例如 StereoNav v1 的 §4.1 明确包含目标位置线索和双目观测；若本研究只允许单目 RGB 加指令，就必须先核对信息差异。[原文](https://arxiv.org/html/2605.13328v1#S4.SS1)

## 7. 运行前登记与运行后审计

运行前记录研究问题、主要预测、对照/消融、数据和 split、seed 列表、训练预算、checkpoint 选择、主要指标、统计单位和异常处理。区分方法效果、工程正确性和资源可行性，不能用任意 accuracy cutoff 代替三者各自的证据。

本地预先登记是带日期、可审查的方案记录，不冒称已在外部平台注册。协议变更建立新版本并说明原因；看到结果后想到的分析标为探索性。

运行后由用户提供结果，审计者检查 manifest、schema、episode 数量/重复/缺失、所有预定 seeds 和失败原因，并从逐 episode 输出复算。使用直接数据比较和 diff，不生成任何哈希校验。数据不足时列出限制，不能把空缺填成 0、复制其他 seed 或用插值伪造实验。

报告至少说明：比较条件、每个 seed 的结果、配对差值、样本数与失败数、主要指标与相关次要指标、可合理估计的不确定性、实际资源、消融与限制。只在统计假设和数据量支持时做推断；没有不确定性证据时不写“显著”“稳定”。

## 8. 最小记录组织

下列为需要时使用的布局，不代表已有实验或已创建全部文件。小任务可以合并成一个 Markdown，避免为了流程制造空记录。

```text
docs/research/<topic>/
  protocol.md          # 任务、方法数学说明和预先登记
  evidence.md          # 论文与断言记录
  decisions.md         # 决策、否定尝试、未知项和更正，追加保存
  review.md            # 数学/协议/实现/结论的审查
  results_audit.md     # 用户提供结果后的复算与限制
```

当前 RoPE Stage 1 以 `rope_public_data_experiment_plan.md`（PUB-R1.1）为唯一现行协议；`spatial_rope_research_plan.md` 作为原始历史方案保留，不为采用本流程改写已经完成的结果。VLN 实验须等任务与基线明确后另建具体协议，本次文档不是 VLN 启动授权。
