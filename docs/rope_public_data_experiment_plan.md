## 1. 本次验收决定什么

本计划使用公开数据集已经发布的图像、问题和答案，不自行渲染场景、合成纹理、生成问题、制造负例或重写标签。SYN-R1.0 的自制单 patch 数据、四元组与联合正确率全部撤销。

下一阶段主路径已确立为 **CLEVR 官方现成 RGB + 原始问题文本上的单关系存在性问答**。这是新的 3 通道问答入口，不是既有 `RGB + marker` 四/五通道任务的直接续跑；现有 schema、源代码、研究计划与历史结果均保留，不由本协议覆盖。

当前唯一主比较仍是 G 与 B。Mixed 是已有方法参照，不是本项目创新。研究目标是先得到可审计的任务证据，再判断是否值得提出一个最小、可证伪的新机制；本计划不保证实验会支持 B，也不预先保证任何未来机制的新颖性或有效性。

本任务不再把 same/cross-region 当作主机制指标，也不宣称可以由问答准确率直接证明跨区域相位机制。自然图像外部验证属于后续阶段，不与本轮预算混算。

## 2. 数据来源、可见字段与筛选

### 2.1 使用已发布数据

主数据为 [CLEVR v1.0 官方数据](https://cs.stanford.edu/people/jcjohns/clevr/)。官方页面提供完整数据下载，包含 train/val 图像、问题答案及场景标注，数据许可为 CC BY 4.0。这里使用的是作者已经发布的渲染图，不能称作自然照片；不使用其图像或问题生成器。

数据由用户下载并提供本地根目录。当前验收路径为 `data/CLEVR_v1.0`，实现仍须要求调用方显式传入根目录，不自动搜索或下载替代副本。预期读取以下官方文件：

```text
CLEVR_v1.0/
  images/train/
  images/val/
  questions/CLEVR_train_questions.json
  questions/CLEVR_val_questions.json
  scenes/CLEVR_train_scenes.json
  scenes/CLEVR_val_scenes.json
  LICENSE.txt
```

模型输入只包含 RGB 与原始问题文本。模型不得读取程序、场景图、对象索引、对象坐标、关系表、筛选结果编码、答案或文件编号。程序只用于离线筛选，场景信息只用于隔离审计；这些字段不经 dataset 返回给模型。原始 ID 用于溯源与划分，不能作为模型特征。

### 2.2 筛选已有问题，不生成新问题

保留以下完整线性程序对应的官方问题与原答案：

\[
\texttt{scene}\to\texttt{filter}_{*}^{\,*}\to\texttt{unique}
\to\texttt{relate}(r)\to\texttt{filter}_{*}^{\,*}\to\texttt{exist}.
\]

发布文件的程序节点按 `function / inputs / value_inputs` 解析；不得与生成器内部的 `type / side_inputs / nodes` 格式混用。精确准入规则为：

1. 首节点是唯一的 `scene`，`inputs=[]`；第 \(j>0\) 个节点的 `inputs` 必须恰好为 `[j-1]`，无分支或未使用节点。
2. `unique` 与 `relate` 各恰好一次，`unique` 紧接于 `relate` 之前；末节点唯一为 `exist`。
3. 两段 filter 链均允许零次或多次，只允许 `filter_color`、`filter_shape`、`filter_size`、`filter_material`。参数的个数、类型和取值须满足官方 schema。
4. `relate` 的唯一关系参数属于 `left / right / front / behind`；官方 `answer` 严格为 `yes` 或 `no`。
5. 不依据答案、对象坐标、目标距离、same/cross-region、模型表现或候选方法的优势筛选。

这是“是否存在满足描述及关系的物体”，不要求目标集合只有一个物体。模型输出 `no=0 / yes=1`，不得用像素中心差替换官方关系。官方执行器的 `relate` 读取关系标注，`exist` 判断集合非空；审计复算与官方答案不一致时报告错误并停止验收，不能自动修正标签。[官方执行语义](https://github.com/facebookresearch/clevr-dataset-gen/blob/main/question_generation/question_engine.py)

### 2.3 先按图像划分，再筛选问题

分别从官方 train、val 完整场景清单取得图像母集，验证 ID 唯一，按 `(int(image_index), image_filename)` 升序排列，使用 NumPy `Generator(PCG64(seed)).permutation(N)`，种子分别为 `20261016`、`20261017`，各执行一次置换。令两个母集图像数为 \(N_{tr},N_{val}\)：

| 用途 | 母集及切分 | 允许用途 |
| --- | --- | --- |
| train | train 置换前 \(\lfloor0.9N_{tr}\rfloor\) 张 | 梯度更新、训练词表 |
| dev | train 的剩余图像 | 诊断与候选机制设计 |
| 基础测试 | val 置换前 \(\lfloor N_{val}/2\rfloor\) 张 | 基础协议冻结后一次评估 |
| 确认保留集 | val 的剩余图像 | 最多一个未来预注册候选与对照的独立确认 |

同图所有问题必须同属一个划分。筛选后没有合格问题的图像不进入训练或指标计算，但仍保留在原始划分清单中。以上不是 CLEVR 官方 test，也不是官方全任务排行榜复现。

数据验收报告须列出各划分实际有效图像数、问题数、四关系 × 两答案的计数、排除原因、原始 ID、文件可读性及 schema 结果。样本数在本地验收前不虚构。缺文件、错误 schema、跨划分泄漏、答案不一致、训练集缺少任一答案类别或目标关系、任一所需评估集合为空时停止，不补造样本、不自动改变准入规则。评估中空的关系 × 答案 cell 标为 NA，不把剩余 cell 的均值冒充完整八格 macro。

确认保留集只做隔离的完整性与类别覆盖检查，不展示模型输出、错误案例或用于设计的统计探索。所有清单使用直接可解释的 ID、字段、文件大小和计数，不做哈希验证。

## 3. 位置变换的数学契约

模型网格为 \(14\times14\)，patch 坐标 \(p_i=(x_i,y_i)\in\{0,\ldots,13\}^2\)。每头维度为 64，含 32 个二维旋转平面；Axial 前 16 个为 x 平面，后 16 个为 y 平面。每轴频率为

\[
\omega_t=100^{-t/16},\qquad t=0,\ldots,15.
\]

对一个轴坐标 \(p\)，G 的相位为 \(\phi_t^G(p)=\omega_t p\)。B 保留 \(t<8\) 的全局相位；对 \(t\ge8\)，

\[
o(p)=7\lfloor p/7\rfloor,\qquad u(p)=p-o(p),\qquad
\phi_t^B(p)=\omega_t[p-\lambda o(p)],\qquad\lambda=1.
\]

令 \(R(\phi)=\begin{pmatrix}\cos\phi&-\sin\phi\\\sin\phi&\cos\phi\end{pmatrix}\in\mathbb R^{2\times2}\)。所有正式组的 CLS 均不旋转。对一对 patch 的二维特征 \(q_i,k_j\in\mathbb R^2\)，旋转后的内积为

\[
(R(\phi_i)q_i)^T(R(\phi_j)k_j)
=q_i^T R(\phi_j-\phi_i)k_j.
\]

必须区分以下数学事实与待验证假说：

- 同一区域的指定 patch 对，其局部相对相位与 G 相同；这不推出整层或整网输出相同，其他 patch 与 CLS 仍参与运算。
- \(\lambda=0\) 恢复 G；旋转保持每个平面的范数和 self-pair 相位。
- 边界例：\(7-6=1\)，但 \(u(7)-u(6)=0-6=-6\)。这是局部平面的方向/距离变化，不证明保留全局平面的整网无法判断方向。
- 局部别名例：\(u(0)=u(7)=0\)，但 G 的其他平面仍可能区分两者。
- 在同一平面用相同频率补回原点，\(R(\omega u)R(\omega o)=R(\omega p)\)，精确恢复 G，不能据此宣称新增表达机制。
- 由于 CLS 不旋转，patch–patch 相对性不能直接提升为整个分类模型的严格平移不变性。

B 的任务收益、跨 seed 稳定性及其解释均是实验问题，不是上述等式的推论。

## 4. 公共模型与比较组

### 4.1 输入到输出

发布 PNG 转 RGB，再转 FP32 张量除以 255，使用锁定 torchvision 版本的双线性、`antialias=True` 整图 resize 至 224×224。没有裁剪、翻转、颜色增强、Mixup、CutMix 或测试增强。resize 不改变官方答案，也不把图像空间变化解释为新的三维标注。

令 \(N\) 为 batch 大小，\(c\in\mathbb R^{192}\) 为可训练 CLS 向量，\(h\in\mathbb R^{N\times192}\) 为问题编码；相加时广播 \(c\)。模型接口为：

\[
X\in\mathbb R^{N\times3\times224\times224}
\longmapsto Z\in\mathbb R^{N\times196\times192},
\]
\[
\text{问题 tokens}\longmapsto\operatorname{Embedding}_{64}
\longmapsto\operatorname{GRU}_{192}\longmapsto h,\qquad
\mathrm{CLS}_0=c+h,
\]
\[
[\mathrm{CLS}_0;Z]\longmapsto6\text{ 层 ViT}
\longmapsto\operatorname{LN}(\mathrm{CLS}_6)
\longmapsto\operatorname{Linear}_{192\to2}.
\]

共同骨干为 Pre-LN、宽度 192、3 头、head_dim 64、MLP 宽度 768、GELU、LayerNorm epsilon \(10^{-6}\)、patch16；QKV 和 patch projection 均使用 bias。无 APE、RPB、QK normalization 或局部 attention mask；CLS 不旋转。所有 dropout 和 drop-path 为 0，LayerScale 初值为 \(10^{-4}\)，并参与训练。

默认复用项目现有非原位 `manual` attention 适配器，四组后端相同；不使用上游向 Q/K 视图原位赋值的路径。未来 SDPA 优化须单独通过等价和梯度回归，不在本轮混用后端来制造速度或精度差异。

GRU 为单向、单层，输入宽度 64、隐藏宽度 192；取包含 END 的最后有效 token 状态，不取 padding 之后的状态。`Embedding.padding_idx=0`，动态 padding，保留真实长度、不截断。回答头复用按上述尺寸、深度与 `num_classes=2` 构造的 `RoPEClassifier` 的 `backbone.head` 及上游 Linear 初始化；不再同时声称它使用另一套默认初始化。只对新增 Embedding/GRU 使用锁定 PyTorch 版本的默认初始化，不调用额外的全模型初始化覆盖骨干。最终两个 logits 平票时预测 0。

### 4.2 文本编码契约

仅从入选训练问题建立词表。保持原问题大小写，不另做空白归一化；分号与逗号前插入分隔空格，移除问号与句号，按单个空格分隔符切分，添加 START/END。若出现连续空格，保留该规则产生的空 token，不静默切换成另一套分词规则。固定 `<NULL>=0`、`<START>=1`、`<END>=2`、`<UNK>=3`；普通 token 按字符串排序分配 ID，最低出现次数为 1。dev/test 未知 token 映射 UNK，禁止扩词表。

该格式参考 [CLEVR-IEP 的公开预处理规范与源码](https://github.com/facebookresearch/clevr-iep/blob/main/iep/preprocess.py)，但其仓库 [LICENSE 为 CC BY-NC 4.0](https://github.com/facebookresearch/clevr-iep/blob/main/LICENSE)，不能与 CLEVR 数据许可混同。默认不引入或直接复制其源码；以 Python 标准库字符串和字典操作组合实现上述显式编码契约，并在 PR 记录不直接采用该源码的理由。如需复制或改写其源码，先完成许可证兼容性确认。该编码不是新的分词算法，也不是新的训练问题生成过程。

### 4.3 正式运行组

| 组别 | 与共同骨干的差别 | 解释范围 |
| --- | --- | --- |
| G | 第 3 节全局 Axial，base100 | 主基线 |
| B | 第 3 节固定低频局部重置，无新增可训练 PE 参数 | 唯一主比较 B−G |
| M10 | 官方 Mixed 参数化，base10、各层各头二维频率可学习 | 已有方法的整体参照，不隔离单一因素 |
| Q-only | 使用 G 的位置结构，绕过整个 patch projection，直接输入 196×192 零 token | 问题先验与非视觉计算对照 |

M10 每层每头以 \(10^{-t/16}\)、\(t=0,\ldots,15\) 为幅值，使用独立随机角度产生两组正交二维方向，得到 32 个二维频率向量，然后直接学习其分量。新增参数为 \(6\times3\times32\times2=1152\)。平面顺序与广播维度对照上游实现；可学习频率的相位不能跨更新缓存或 detach。[官方 RoPE-ViT 实现](https://github.com/naver-ai/rope-vit/blob/main/models/vit_rope.py)

M10 不是完整官方架构/训练配方复现。M10−G 同时改变频谱、方向参数化与可学习性，不能将其收益归因于其中一个因素。

Q-only 不调用 RGB loader，也不读取 scene；零 token 是模型输入消融，不是新图像或合成训练数据。其后续 patch token 正常参与计算和更新；保留的 patch projection 参数不参与前向，梯度为 None。不能声称每个参数都同等有效训练。

另设不训练的 `train-majority`：总是预测入选训练问题中较多的答案，平票预测 no。不能按测试集或按各关系单独选择多数类。

## 5. 初始化、训练与资源预算

### 5.1 公共初始化与参数组

每个 seed 生成一次包含视觉骨干、语言模块和回答头的公共非 PE 初始状态，复制给所有组；先核对键名、shape、dtype，再逐 tensor 用 `torch.equal` 比较。M10 频率使用独立随机流，不能改变共同初始化或样本顺序。共同初始化不等于冻结：所有实际参与前向的可训练参数均正常优化。

AdamW 参数组必须逐项记录，每个可训练参数恰好属于一个组：

| weight decay | 参数 |
| --- | --- |
| 0.05 | Conv、QKV/输出/MLP/回答 Linear 权重；Embedding 权重；GRU 的 `weight_ih`、`weight_hh` |
| 0 | 全部 bias（包括 GRU 两组 bias）；LayerNorm 参数；CLS；LayerScale；M10 频率 |

Q-only 的未使用 patch projection 梯度保持 None，不能人为预分配零梯度而使其受到意外更新。保存所有初始 state，不做哈希校验。

### 5.2 固定配方

| 项目 | 本版选择 |
| --- | --- |
| 正式 seed | 101、102、103、104、105 |
| 每 run 预算 | 8000 次 optimizer 更新 |
| 有效 batch | 128；单 GPU，micro-batch16，累积8次 |
| 优化器 | AdamW，betas=(0.9,0.999)，epsilon=1e−8 |
| 损失 | 两类交叉熵，无 label smoothing |
| 梯度 | micro-batch 均值损失先除以8；累积后全局范数裁剪1.0，再更新 |
| 精度 | FP32，关闭 AMP、TF32 |
| checkpoint | 初始状态及每1000步保存；主结果固定取8000步，不选最佳 dev |
| 评估 | 每1000步 dev；结束时完整 train；基础测试须另行获准 |

第 \(k\) 次更新的学习率是：

\[
\eta_k=\begin{cases}
3\times10^{-4}\,k/400,&1\le k\le400,\\
10^{-6}+\dfrac{3\times10^{-4}-10^{-6}}2
\left[1+\cos\left(\pi\dfrac{k-400}{7600}\right)\right],&400<k\le8000.
\end{cases}
\]

这是预先选择的共同预算，不是最优性或收敛保证。低分不自动延长训练；若 G/M10 都未建立有效任务学习，只能说本配置不足以定位 PE 问题，不能宣布 RoPE 失效。

训练问题的基础顺序按 `(image_index, question_index, 原数组位置)` 排列。样本流采用独立 PCG64，种子 `10000+s`，四组同序；每轮无放回遍历，尾部不足 batch 时接下一轮置换补齐，不 `drop_last`。M10 初始化 seed 为 `20000+s`。

### 5.3 运行矩阵

| 阶段 | 运行矩阵 | optimizer 更新数 |
| --- | --- | ---: |
| 数据/源码验收、数学与工程检查 | 不训练；另行获准后执行 | 0 |
| 公共 pilot | 4组 × seed9001 × 800步 | 3200 |
| 正式基础实验 | 4组 × 5seed × 8000步 | 160000 |
| 合计 | 24个训练 run，其中20个为正式 run | 163200 |

合计 20,889,600 次训练样本呈现，不包含评估、返工或未来新候选。pilot 使用正式调度的前800步，正式 run 从各自 seed 的初始状态重新开始，不继承 pilot 权重。

pilot 仅检查数值、梯度、资源与实现，不利用 B 的优势或测试表现选配方。错误先复现、最小化、提出可证伪假说、针对性观测、确认根因，再最小修复并回归；修订须升版并共同重跑 pilot，额外开销重新批准，不无限调参。

GPU 小时、显存和吞吐由获准启动后的 pilot 测量，当前不虚构估计。GPU 计算时间和包含数据 I/O 的端到端时间分开报告；Q-only 不读图的优势不是 PE 加速。显存不足须统一修订 micro-batch/累积方案并保持有效 batch，不允许不同组自行更换精度或预算。

### 5.4 恢复与完成记录

仅在完整更新边界保存：模型、optimizer、scheduler、更新编号、sampler 当前置换及已消费游标、Python/NumPy/PyTorch/CUDA RNG。不能把 DataLoader 预取位置当作已消费位置。恢复后直接核对接续样本 ID 和状态；不能从 checkpoint 重新开始整轮采样。

运行配置展开记录实际软件版本、设备、后端和确定性设置，不承诺跨硬件 bitwise 一致。runner 自身记录完成状态、最后一步及异常退出；代理不主动轮询运行情况。

## 6. 数学与实现验收

独立保真 FP64 参考采用实旋转矩阵，不经过 vendor 的 `.float()` 路径；生产参考显式匹配 Q/K 转 FP32、phase dtype、复数运算及输出转换。输出 dtype 为 FP64 不代表内部做了 FP64 计算。

初始状态复制采用精确比较；数值回归采用 [PyTorch 2.6 `assert_close` 的 dtype 约定](https://docs.pytorch.org/docs/2.6/testing.html)：FP32/complex64 的 rtol=1.3e−6、atol=1e−5；FP64/complex128 的 rtol=atol=1e−7。按实际计算精度而非回转后的输出 dtype 选择，并记录输入范围、最大绝对误差及范数误差。这是库级约定，不是假称已推导的误差上界；失败时诊断原因，不事后任意放宽容差。

必须覆盖：

- 第3节相对内积、旋转范数、self项、同区域指定 pair、边界与别名例、B在lambda=0时恢复G。
- M10 的平面/层/头维度与上游算子一致，前向及 Q/K、频率梯度通过独立检查；不能以“采用非原位实现”替代正确性证明，也不复用失效的相位计算图。
- 保真 FP64 的梯度检查与实际生产精度回归分开，不能以一种替代另一种。
- 同 seed 的公共初始状态及样本序列一致，真实长度而非 padding 决定 GRU 最终状态。
- 数据错误与正常任务排除分开，原答案不能被审计程序改写，测试/确认样本不能进入训练词表或优化。
- Q-only 不读取图像/scene，未使用 patch projection 不更新；checkpoint 恢复保持下一批样本与更新状态一致。

数学检查允许最小张量例子，但它们不是自行制作的训练/评估数据集，不能计作任务证据；执行检查仍需用户启动授权。

## 7. 指标与统计

唯一主指标是基础测试全部入选问题的微平均准确率。对每个配对训练 seed \(s\)，报告

\[
\Delta_s=\operatorname{Acc}_{B,s}-\operatorname{Acc}_{G,s}.
\]

M10−G 为次级比较。辅助报告交叉熵、四关系 × yes/no 的八格计数和准确率、八格等权 macro、Q-only 与 train-majority。空 cell 标 NA，不隐藏或悄悄重定义 macro；本轮不使用四元组或联合正确率。

训练变异：公开五个 seed 的各组结果和全部配对差，给出均值、样本 SD 与近似区间

\[
\bar\Delta\pm t_{4,0.975}\,s_\Delta/\sqrt5.
\]

它条件于固定数据集和协议，依赖小样本近似假设，不包含重新抽取训练数据的变异，不承诺显著性。区间包含0不等于证明严格无效。

测试因子变异：固定已训练模型，使用 seed31001 做2000次按图像聚类 bootstrap，只在有入选问题的测试图像中有放回抽样，保留同图全部问题。所有方法、所有训练 seed 共用抽样索引。若图像 \(i\) 有 \(n_i\) 个问题、方法 \(m\) 在 seed \(s\) 下答对 \(c_{m,s,i}\) 个，抽样重数为 \(w_i^{(b)}\)，则

\[
\operatorname{Acc}_{m,s}^{(b)}=
\frac{\sum_iw_i^{(b)}c_{m,s,i}}{\sum_iw_i^{(b)}n_i}.
\]

每次求五 seed 的平均 B−G 差，再取2.5%/97.5%百分位区间。不能改成先算每图准确率再平均，不能把2000次 bootstrap 当成独立训练次数，也不能把它与训练变异区间拼成一个总体区间。

保留未经挑选的逐问题 ID、标签和两个 logits，支持独立重算。不得仅报告最好 seed、最好 checkpoint 或最有利切片。

## 8. 如何进入有意义的新机制

基础计划不是新 RoPE 方法的有效性验证。跨 seed 稳定错误也可能来自识别、语言条件接口、模型容量或优化，不足以定位位置编码瓶颈。

只有以下证据和定义齐备，才申请一个最小候选的实现与试验：

1. RGB 模型相对 Q-only 和训练先验存在可重复的任务增量，报告效应与不确定性；这只是视觉信息有用，不单独证明空间机制正确。
2. 指出一个具体相位机制假说：哪种任务条件、哪个相位项、预期造成哪类错误，并给出手算例、边界条件与可反驳的预测。
3. 预注册竞争解释对照：如何在 dev 上区分该假说与一般识别/语言/优化问题。保持视觉与语言组件一致，匹配训练、选择和计算预算，比较适用的普通调频或既有方法，而不是只比较一个弱基线。候选确认至少包含 G、M10 和最近的已知方法；若最近方法就是前两者之一，不重复运行或虚增对照数。

候选数学说明至少包含：符号与张量维度、输入输出域、精确公式、与G和最近方法的差异、初始化退化、不变量与例外、正交性及相对性范围、梯度与数值策略、参数/计算增量、最强反例、预期改善及不应改变的样本条件、唯一确认指标。先推导再实现，不能根据结果倒推理论。

排重应阅读原文公式和官方实现，至少核查 RoPE-Mixed、PoPE，以及一个与实际候选最接近的方法，并覆盖当时的新近工作。要排除同平面旋转叠加、可吸收换基或普通调频造成的伪新增表达能力。若确属等价重参数化，只能另行检验优化收益，不能声称新增表示能力。[RoPE-Mixed](https://arxiv.org/abs/2403.13298)、[PoPE](https://arxiv.org/abs/2509.10534)

保持一次标准 attention 的兼容性是当前低成本工程目标，不是所有创新的数学必要条件。联合训练允许；冻结骨干探针不是所有方法的必要门槛。单纯 F/J 增大、attention 图变化或对相位敏感，都不是充分的机制或收益证据。

决策按证据执行：

- 若只有 B 失败，优先放弃该 reset，不据此指控 RoPE 整体。
- 若已有 M10 解决目标问题，记录已有方法有效，不另造模块包装创新。
- 若 G/M10 均未学会任务，先说明配置/优化/感知能力尚不足以定位问题，不盲目扩张 PE 变体。
- 若一个候选具备上述定义与对照，另行提交预算和预注册；最多一个候选及其冻结基线进入确认保留集。
- 确认集用过后不能反复用于挑选新方法；新候选需要新的独立确认协议。即使通过，本轮结论仍局限于 CLEVR，而不是自然图像通用空间理解。

当前20个正式 run 不包含未知候选及最近方法的新增训练。最终验收本计划不等于验收尚不存在的新模块。

## 9. 成熟库选型与后续数据边界

以下是实施前选型方向，不表示已安装或引入新依赖。每个实现 PR 仍须核实具体版本、文件许可、维护状态和实际 API；复用核心模块，仅写任务特有薄适配。

| 候选 | 采用范围与理由 | 不采用或需保留的边界 |
| --- | --- | --- |
| 官方 CLEVR 数据与生成器文档 | 已发布数据、schema、关系语义 | 不运行生成器；数据许可与代码许可分开 |
| 项目 vendored RoPE-ViT | 已有骨干、Axial/Mixed频率算子、平面顺序 | 保留文件级许可；不加载预训练；不直接复用原位Q/K写入路径 |
| PyTorch、torchvision、timm | GRU/Embedding/优化器/图像处理/PatchEmbed | 沿用项目已记录的2.6.0/0.21.0/1.0.24作为候选栈，实施前核实实际版本，差异显式记录 |
| NumPy、Python标准库、PIL | PCG64划分/采样、JSON、文本编码与本地图像解码 | 记录实际版本；不引入下载或哈希检查 |
| CLEVR-IEP | 仅参考公开文本格式 | CC BY-NC 4.0，默认不直接引入源码；具体见4.2 |

官方旧研究仓库不自动等于维护中的通用库；成熟的张量、GRU、优化器和图像算子优先由当前项目库提供。自定义缺口仅包括只读问题筛选、数据契约、问答接入、配对运行与统计，不能重写已有 Transformer/GRU 核心来增加维护面。

自然图像验证优先考察 [SpatialSense 官方任务](https://github.com/princeton-vl/SpatialSense)，其 [Zenodo 发布页](https://zenodo.org/records/8104370) 列出已发布图像包和标注。它是给定对象对及关系的真伪判断，不是自制二维方向标签。图像使用许可尚须单独核实，代码许可证不能代替图像许可；在许可和任务接口确定前不启动，也不计入当前已完成证据。

[Rel3D](https://github.com/princeton-vl/Rel3D) 有作者发布的对比样本与数据接口，可作为需要对比关系任务时的后续候选，本轮不并行加入。不自行渲染其场景，也不假定它提供任意四元组。任何后续数据集均需单独给出输入、原标签、划分、成本及结论范围。

## 10. 实施顺序、交付与权限

拟议实现单元如下，均为待创建的真实 PR，不是已经存在的 PR 编号：

1. 只读数据契约、筛选/审计/划分和文本编码。
2. 公共问答骨干、G/B接入与数学/数值回归。
3. M10与Q-only接入、上游映射及梯度检查。
4. 配对初始化、采样、训练、checkpoint与恢复。
5. 聚类统计、完整报告与经批准的主入口切换。

每个独立最小功能通过测试、形成可审查 PR 后，再开始下一个；实际单元仍可为保持“一 PR 一问题”继续拆分。PR 描述包含问题与触发条件、数学依据、库与许可检索、最终改动、测试证据和未覆盖范围。

交付包括：协议版本、数据验收报告、原始ID/划分/词表清单、精确配置及环境、源码与PR记录、公共初始state、逐更新样本顺序、完整日志/checkpoint、逐问题预测、全部seed统计、计算/I/O成本与失败修订记录。用户提供结果后再独立复算，不以双方模型讨论共识代替实验证据。

协议已获用户验收，当前授权仅覆盖按本节顺序创建独立实现 PR 及其单元/回归测试；不授权下载数据或权重，也不自动授权工程冒烟、pilot、正式训练或基础测试评估。数据与权重始终由用户提供；这些运行阶段仍分别等待明确启动指令。进程启动后代理不主动轮询日志、GPU、指标或进程，只有用户要求时进行一次按需检查。

源码实施前完成数学说明和成熟库检索；每个最小功能使用独立分支，通过真实 PR 交付。未合并、未复现前不创建或声称存在 release tag。协议文档 PR 不混入 Python、README 或旧研究计划修改。
